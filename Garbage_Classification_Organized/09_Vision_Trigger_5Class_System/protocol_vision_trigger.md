# 串口协议文档 — 五分类视觉触发版

> 版本：vision_trigger_5class_v1
> 状态：最终可运行系统

---

## 1. 新版串口协议表

### 树莓派 → MCU

| 字符 | 含义 | 说明 |
|------|------|------|
| `R` | 可回收 | Recyclable — 舵机转到可回收垃圾桶 |
| `K` | 厨余 | Kitchen — 舵机转到厨余垃圾桶 |
| `H` | 有害 | Harmful — 舵机转到有害垃圾桶 |
| `O` | 其他 | Other — 舵机转到其他垃圾桶 |

**注意**：「待分拣」不对应任何串口命令。见第 4 节说明。

### MCU → 树莓派

| 字符 | 含义 | 说明 |
|------|------|------|
| `D` | 分拣完成 | Done — 当前分拣动作已执行完毕 |
| `F` | 满载暂停 | Full — 垃圾桶已满，暂停分拣 |
| `N` | 满载解除 | Normal — 垃圾桶已清理，恢复正常 |
| `E` | 错误 | Error — 超时/异常/非法命令 |

---

## 2. R/K/H/O 含义

这四个字符由树莓派在 AI 模型稳定识别后发送给 MCU，指示 MCU 将舵机转向对应垃圾桶并执行推出/回位动作。

| 字符 | 中文类别 | MCU 舵机角度（参考旧版） |
|------|----------|--------------------------|
| `R` | 可回收 | angle_pwm = 8 |
| `K` | 厨余 | angle_pwm = 29 |
| `H` | 有害 | angle_pwm = 19 |
| `O` | 其他 | angle_pwm = 36 |

> 舵机角度以 MCU 固件实际定义为准，以上为参考值。

---

## 3. D/F/N/E 含义

| 字符 | 含义 | 树莓派响应 |
|------|------|-----------|
| `D` | MCU 已完成分拣动作 | 进入 WAIT_RETURN_TO_PENDING，等待画面回到「待分拣」 |
| `F` | MCU 满载传感器触发 | 进入 FULL_PAUSED，暂停所有分拣命令 |
| `N` | MCU 满载解除 | 从 FULL_PAUSED 回到 IDLE_WAIT_VISUAL |
| `E` | MCU 报告错误 | 进入 ERROR_RECOVERY，根据错误计数决定重试或报警 |

---

## 4. 为什么移除 T

旧版协议中 `T` 由 MCU 发送给树莓派，表示"超声波检测到物体，请进行 AI 识别"。

**移除原因：**

1. **视觉触发替代距离触发**：新版系统由摄像头持续推理，不需要外部传感器通知"有物体"。
2. **「待分拣」类处理等待状态**：模型自动判断画面中是否有垃圾，无需 MCU 参与判断。
3. **减少串口交互**：移除 T 后，MCU 只需被动接收分类命令和返回状态，通信更简单。
4. **降低硬件复杂度**：不再需要 HC-SR04 超声波模块及 TRIG/ECHO 引脚。

---

## 5. 为什么移除超声波

| 对比维度 | 超声波 (HC-SR04) | 视觉触发（新版） |
|----------|------------------|-------------------|
| 触发方式 | 距离阈值 | AI 图像分类 |
| 能区分垃圾类型 | 否 | 是（同时完成分类） |
| 误触发风险 | 手、衣物等靠近会触发 | 模型训练后可区分 |
| 硬件依赖 | TRIG + ECHO 引脚 | 仅摄像头 |
| 系统复杂度 | 需要 MCU 主动发起 T | 树莓派自主决策 |

---

## 6. 「待分拣」为什么不对应串口命令

「待分拣」是**视觉等待状态**，不是垃圾类别。

- 含义：画面中没有需要分拣的垃圾，或系统处于等待下一件垃圾进入的状态。
- 模型输出「待分拣」时，树莓派**不发送任何字符给 MCU**。
- `class_mapping_5class.json` 中 `no_action_classes` 明确列出「待分拣」。
- `action_mapping` 中不包含「待分拣」→ 无对应串口字符。

这样设计的好处：
- 避免 MCU 收到无意义的"不动作"命令。
- 让串口通信只承载实际分拣指令，语义清晰。
- 降低 MCU 固件复杂度。

---

## 7. MCU 的职责

1. 接收树莓派发送的 `R` / `K` / `H` / `O` 单个字符。
2. 根据字符控制舵机转向对应垃圾桶。
3. 控制电机执行推出/回位动作。
4. 完成分拣动作后，向树莓派发送 `D`。
5. 检测满载传感器状态：
   - 满载时发送 `F`，禁止开门。
   - 满载解除后发送 `N`。
6. 检测异常情况，必要时发送 `E`。
7. **MCU 不再搭载超声波传感器，不再主动发起 T 触发。**

---

## 8. 树莓派的职责

1. 持续从摄像头获取画面帧。
2. 使用 TFLite 模型对每帧进行五分类推理。
3. 根据状态机逻辑判断是否发送分拣命令。
4. 通过串口向 MCU 发送 `R` / `K` / `H` / `O`。
5. 监听 MCU 返回的 `D` / `F` / `N` / `E`，更新状态机。
6. 确保每次分拣后画面回到「待分拣」才允许下一次分拣。
7. 满载时暂停所有分拣命令。
8. **树莓派不再等待 MCU 发送 T 才推理，始终保持推理状态。**

---

## 9. 异常情况处理建议

| 异常情况 | 建议处理 |
|----------|----------|
| 发送 R/K/H/O 后超时未收到 D | 进入 ERROR_RECOVERY，记录错误。可尝试重新发送（最多 N 次），超过后报警。 |
| 收到 E | 记录错误代码（如 MCU 扩展协议）。进入 ERROR_RECOVERY，等待恢复条件满足后回到 IDLE_WAIT_VISUAL。 |
| 串口通信中断 | 检测串口异常，尝试重连。重连成功后初始化状态机到 IDLE_WAIT_VISUAL。 |
| 模型连续多帧置信度低迷 | 记录预警日志。可能原因：光照剧变、摄像头遮挡、模型不匹配。 |
| 满载持续时间过长 | 记录预警日志，可触发蜂鸣器或指示灯提示用户清理。 |
| 模型将空画面误判为垃圾类别 | 依赖「待分拣」类的训练质量和 recall。如果误判率高，需增强「待分拣」数据集。 |

## 10. 与旧版协议对比

| 项目 | 旧版（AA55 / ASCII RKHO） | 新版（视觉触发） |
|------|--------------------------|------------------|
| MCU→RPi | T / F / N / D / E | F / N / D / E（**T 已移除**） |
| RPi→MCU | R / K / H / O | R / K / H / O（不变） |
| 触发机制 | MCU 超声波主动发 T | 树莓派视觉自主判断 |
| 类别数 | 4（其他/厨余/可回收/有害） | 5（+ 待分拣） |
| 传感器 | HC-SR04 超声波 | 仅摄像头 |
| 等待状态 | MCU 端 TRIGGER_COOLDOWN_MS | 树莓派端 WAIT_RETURN_TO_PENDING |
