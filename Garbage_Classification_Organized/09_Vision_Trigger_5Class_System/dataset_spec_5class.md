## 3. 「待分拣」类详细规范

### 3.1 定义

「待分拣」不是垃圾类别，而是**系统等待状态**。它表示：
- 分拣平台上没有任何垃圾物体。
- 用户已投放一件垃圾但尚未到达平台中央。
- 上一件垃圾分拣完毕后平台恢复空置。
- 系统可以安全接收下一件垃圾。

### 3.2 必须包含的场景

| 场景 | 说明 |
|------|------|
| 空平台 | 分拣平台上无任何物体，正常背景 |
| 正常光照空平台 | 室内常规灯光下的空平台 |
| 弱光空平台 | 光线较暗时的空平台 |
| 强光空平台 | 阳光直射或强灯照射的空平台 |
| 轻微阴影 | 人体或物体在平台上的投影 |
| 手刚离开 | 用户投放垃圾后手离开平台的瞬间 |
| 分拣后残留 | 分拣动作完成后平台状态，可能有小碎屑 |
| 不同角度 | 摄像头在不同视角下的空平台（如安装位置微调） |
| 背景变化 | 平台背景因环境变化（如更换桌面、移动物品） |

### 3.3 关键质量要求

- **Recall 必须非常高**（建议 ≥ 0.98）：宁可将少量垃圾误判为「待分拣」，也不要将「待分拣」误判为某一类垃圾。
- 如果将空画面误判为「其他」「厨余」「可回收」「有害」之一，会导致**误触发分拣**，造成严重问题。
- 在训练和评估时优先关注「待分拣」与其他四类之间的混淆矩阵。

## 4. 四类垃圾质量要求

| 类别 | 关键指标 | 说明 |
|------|----------|------|
| 其他 | Precision ≥ 0.90 | 避免将其他垃圾误分类而分拣到错误桶 |
| 厨余 | Precision ≥ 0.90 | 同上 |
| 可回收 | Precision ≥ 0.90 | 同上 |
| 有害 | Precision ≥ 0.95 | 有害垃圾误分类风险最高，精度要求更严格 |

## 6. 数据采集注意事项

1. **使用真实部署摄像头角度**：采集时的摄像头位置、角度应与实际树莓派部署一致。
2. **使用真实光照**：避免使用补光灯，模拟实际环境中的自然/室内灯光。
3. **使用真实平台背景**：采集时使用与实际分拣平台相同的桌面/背景。
4. **垃圾物体多样性**：每类垃圾应包含不同形状、颜色、大小的样本。
5. **避免重复**：同一垃圾物体多次拍摄时应更换角度、位置、光照。
6. **「待分拣」类不要包含任何垃圾**：即使是"即将投放"的半截画面也应归入对应垃圾类别。
7. **标注一致性**：如有歧义（如厨余与其他的边界），统一标注规则并记录。
8. **格式统一**：所有图片建议使用 JPG 格式，分辨率不低于 640×480。

---

## 7. 数据集划分建议

沿用旧版划分比例：

| 用途 | 比例 | 说明 |
|------|------|------|
| train | 70% | 训练集 |
| val | 20% | 验证集（模型选择、早停） |
| test | 10% | 测试集（最终评估） |

划分时按类别分层抽样（stratified split），确保每类在三个集合中的比例一致。

---

## 8. class_names.json 格式

划分脚本生成的 `class_names.json` 顺序必须与训练、推理保持一致：

```json
["待分拣", "其他", "厨余", "可回收", "有害"]
```

顺序必须与 `class_mapping_5class.json` 中 `class_to_idx` 的索引一致。

---

## 9. 从旧版四分类迁移

旧版四类：`其他` `厨余` `可回收` `有害` → 保留，对应 idx 1–4。

**迁移策略**：
1. 保留现有四类垃圾的 `dataset/` 和 `garbage_dataset/` 数据。
2. **新增** `待分拣/` 目录，采集新数据。
3. 修改数据集划分脚本以支持五分类。
4. 修改模型训练脚本 `NUM_CLASSES = 5`。
5. 四类垃圾的现有数据可直接复用，只需重新划分。

不建议从零重建数据集。旧数据是宝贵的真实部署数据。
